# ADR-0017: Per-Component Effort Ceilings

- **Status:** Accepted
- **Date created:** 2026-10-09
- **Date modified:** 2026-11-07

## Context

Issue #573 asks for a maximum effort per skill, command and agent, on top of the global ceiling that already exists (`maxEffortLevel`, shipped in #590, #592 and #598). Two limits of Claude Code shape the answer. The `Agent` tool has no per-call effort override, and a hook cannot change a subagent's effort. An agent's effort is fixed by its file, so enforcement for agents can only mean choosing which file to dispatch. Commands and skills set effort in their own frontmatter, and a skill sets none on purpose (`docs/concepts/03-why-the-pieces-are-shaped-this-way.md`).

## Decision

1. **Config keys.** One key per component: `effort.agents.<name>`, `effort.commands.<name>`, `effort.skills.<name>`. The value is `auto`, `low`, `medium`, `high`, `xhigh` or `max`, the same enum as `maxEffortLevel`. `<name>` is lowercase letters, digits and hyphens. Set with `playbook config set --global effort.agents.fact-checker medium`. Only the global tier counts, as for `maxEffortLevel`.
2. **Unknown names warn.** The key shape is validated when it is written. Whether the name exists is checked against the plugin files by `playbook effort list`, which flags a configured name that matches no component. A stale name never fails a command.
3. **Precedence.** The ceiling for a component is the lowest of: Claude Code's `maxEffortLevel` (always the top authority, read only), playbook's `maxEffortLevel`, and the component's own key. `auto` and `max` add no limit. The effective effort is the lower of the component's shipped effort and that ceiling. A ceiling never raises anything. A component that ships no effort (`effort:` absent) inherits the session's effort, so only the session ceiling applies to it.
4. **Agents: variants rendered per session, not committed. Superseded 2026-11-07, see the amendment below.** The base agents are the only files in `agents/`. `playbook agents` keeps a `VARIANTS` table that lists every tier (`low`, `medium`, `high`, `xhigh`, `max`) for every base agent, and `playbook agents check` fails when an agent has no entry or a tier cannot render. A tier equal to the agent's own effort renders nothing, so there is no `-high` variant for an agent that ships at `high`. `ccc` and `ccd` render the variants for one session into a throwaway plugin directory (`playbook-variants-<pid>` in the temp dir, with a manifest and one agent file per variant), pass it with `--plugin-dir`, and remove it when the session ends. Nothing under `~/.claude` or the repo is touched. The variants are agents of that plugin, so they are spawned as `playbook-variants:reviewer-low`. If the directory cannot be written, the launcher falls back to `--agents` (fields `description`, `prompt`, `tools`, `model`, `effort`, all accepted by Claude Code 2.1.293; an invalid `effort` is rejected at startup, which shows the field is parsed). Which variants a session gets is the key `agents.variants`: `auto` (default) gives the cheaper tiers to every agent and `xhigh` to `analyst`, `critic`, `fact-checker`, `implementer` and `reviewer`, `all` adds every other tier including `max`, `off` gives none. A variant above any ceiling in play is never passed. Each variant description is one short line.
   `playbook effort resolve agents <name> --json` returns the shipped effort, the ceiling, the effective level, `subagentType` to spawn, `allowed`, the names at or under the ceiling, and `allowedTypes`, the same names as `subagent_type` values. The launcher names the session's variants in `PLAYBOOK_AGENT_VARIANTS` and the throwaway plugin in `PLAYBOOK_AGENT_VARIANTS_PLUGIN`, which `resolve` reads to build the `playbook-variants:` prefix, so a session started without the launcher reports the base agent only and `satisfied: false` when the base is above the ceiling. The `delegating-subagents` skill runs `resolve` before a spawn and falls back to the base agent when a variant is not listed. Amendment 2026-11-06: `resolve` also returns `effort`, the effective level, and the skill passes it as the `Agent` tool `effort` parameter (Claude Code 2.1.296). The variants stay until the follow-up changes (issue #1380) remove them.
5. **Commands and skills: a lookup.** `playbook effort resolve commands <name>` gives the allowed level. A command's own frontmatter cannot be rewritten per user, so the command text calls `resolve` in its first step (Step 0, next to the run mode) and uses the result to decide which agent variants to spawn. The seven commands that can spawn agents do this, and `tests/commands_effort_ceiling.rs` fails when one stops. Amendment 2026-10-14: the launcher no longer passes `--settings`, and playbook never writes a Claude Code settings file. The global ceiling now lowers the agent variants and the launcher's default effort only. See "What the effort ceiling does and does not cap" in the config keys guide.
6. **Status.** `playbook effort list` prints every component with its shipped effort, configured ceiling and effective level, in a table or as `--json`.

**Amendment 2026-11-07 (issue #1380): the `Agent` tool `effort` parameter replaces the variants.** Claude Code 2.1.296 takes an `effort` parameter on the `Agent` call, and it applies to plugin agents (checked with real spawns: the agent saw a different reasoning effort for no parameter, `high` and `max`). Decisions 1 to 3, 5 and 6 stand. Decision 4 changes:

- The orchestrator spawns the base agent and passes `effort`. `playbook effort resolve agents <name> --json` returns `effort`, the shipped effort lowered by every ceiling, and `ceiling`. The orchestrator never passes a level above `ceiling`. `effort.auto` and the diff-size table pick a level, not a variant name, and raise to `high` at most.
- `agents/variants.rs`, the `VARIANTS` table, `cc/agent_variants.rs`, the throwaway `playbook-variants` plugin, `PLAYBOOK_AGENT_VARIANTS`, `PLAYBOOK_AGENT_VARIANTS_PLUGIN` and `playbook agents variants` are removed. `playbook agents check` no longer keeps a variants table in step. `resolve` drops `file`, `allowed`, `allowedTypes` and `satisfied`.
- The `agents.variants` key is still accepted and does nothing, and `playbook doctor` says so when it is set. The launcher removes a `playbook-variants-<pid>` folder left by an earlier release when no process owns it.
- Why: a spawn by variant name skipped the ceiling check (found while running the ADR 0056 quality gate, where the critic ran at `xhigh` above its `medium` floor). With one parameter, one place sets the effort.
- Still advisory: the ceiling applies when the orchestrator asks `resolve` first. A hook that rejects a spawn above the ceiling is a follow-up. Claude Code versions before 2.1.296 ignore the parameter and the agent runs at its file's effort.

## Alternatives considered

- **Nested `effort.perComponent` object.** Rejected: `playbook config set` takes one dotted key and one scalar, and a nested object would need a second write path.
- **Rewriting agent frontmatter at launch.** Rejected: it edits plugin files, which are replaced on every plugin update, and it cannot differ per session.
- **Committing every variant as a file under `agents/`.** Tried first (`-medium` shipped in #624) and rejected. Claude Code lists every agent's description in each session. Measured on the real agents: 12 base descriptions are 6.3 KB of context, committing 48 variants adds 27 KB (5.3 times the base), while the `auto` set of 19 rendered variants adds 1.9 KB and a `medium` ceiling adds 1.4 KB. #624 was reverted by this design.
- **One `--agents` argument.** Used first and replaced by the plugin directory (2026-10-09, Claude Code 2.1.293). Measured: the `auto` JSON is 100,108 bytes. macOS accepted it, and Linux refuses any single argument of 131,072 bytes or more (tested in a container: 131,071 passes, 131,072 fails with `Argument list too long`), so the margin was 24 percent and every agent edit shrank it. The plugin directory has no limit. It stays as the fallback, with the old trimming at 120,000 bytes.
- **Group keys such as `effort.agents`.** Rejected: a key that holds one level for every agent is `maxEffortLevel` with a narrower name, and a group value next to per-name values needs a fourth precedence step that nobody asked for. Set `effort.agents.<name>` for one agent, or `maxEffortLevel` for all.
- **Failing on an unknown component name.** Rejected: plugin files change between versions and a stale key must not break a session.

## Consequences

- A user can hold `fact-checker` at `medium` and leave `deep-review` at `xhigh`, as long as Claude Code's own ceiling allows it.
- Enforcement for agents is advisory text that names the `effort` to pass (see the amendment) and for commands and skills, plus the global launcher ceiling.
- Users who named a variant such as `reviewer-low` switch to the base agent plus the `effort` parameter (amendment 2026-11-07).
- `playbook agents gen` and then `playbook agents variants` are gone.
